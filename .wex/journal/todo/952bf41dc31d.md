# Scénarios : libérer les acteurs même quand le nettoyage échoue

Constaté sur portfolio : un scénario en échec laissait ses acteurs (`scenario-member@example.com`…) dans la base de test, et chaque run suivant plantait sur des emails en doublon.

## Cause

`ScenarioContext::tearDown()` (`src/Class/Scenario/ScenarioContext.php`) supprime d'abord les données créées par les factories, puis libère les acteurs. La première suppression qui lève une exception — ici une table absente de la base de test — interrompt la méthode : la boucle des acteurs n'est jamais atteinte. Et Doctrine ferme l'EntityManager après une erreur SQL, donc les suppressions suivantes échoueraient de toute façon.

## À faire

- Dans `tearDown()`, tenter chaque suppression puis chaque libération d'acteur même si une précédente a échoué, collecter les exceptions, et relancer la première une fois tout tenté.
- Réinitialiser l'EntityManager fermé entre deux tentatives (`ManagerRegistry::resetManager()`), sinon tout ce qui suit l'erreur échoue aussi.
- Un test qui reproduit le cas : une factory dont `remove()` lève, l'acteur doit quand même être libéré.

## Contexte

Portfolio contourne déjà le problème en reconstruisant sa base de test à chaque run (`tests/bootstrap.php`, commit `d032934`), donc ce défaut ne bloque plus rien là-bas. Il reste vrai pour toute app qui garde sa base de test d'un run à l'autre.
